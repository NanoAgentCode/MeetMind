# 会智录第一阶段功能说明

## 1. 阶段目标

第一阶段交付一个可独立运行的会后会议纪要处理闭环：用户上传录音，系统完成语音转写和结构化纪要生成，用户人工确认后导出正式文档，并能在会议记录中继续管理历史任务。

```text
上传录音
  → 语音转写
  → AI 生成纪要
  → 人工编辑并保存定稿
  → 导出 Word / Markdown
```

本阶段采用“AI 生成、人工确认”的产品原则。未经人工保存的 AI 纪要不能作为正式文件导出。

## 2. 用户功能

### 登录与后台任务（阶段增量）

- 通过 `ADMIN_USERNAME`、`ADMIN_PASSWORD` 初始化首个账号；密码以 PBKDF2 哈希保存，登录后使用可注销的 HttpOnly 会话 Cookie。
- 会议按创建用户归属；旧会议在首次管理员初始化时归属该管理员。会议访问由 RBAC 的本人、部门及下级、全部三档数据范围决定。
- 超过 `BACKGROUND_AUDIO_MB`（默认 20 MB）的文件上传后自动排队转写，服务启动时恢复未完成任务。成功或失败均写入所属用户的站内通知。
- 铃铛通知每 10 秒更新；浏览器页面打开且授予通知权限时，可弹出 Windows 桌面通知。浏览器关闭时不发送系统通知，但站内记录保留。
- 任务队列基于单进程应用与 SQLite；多实例部署需要替换为独立任务队列。外部 ASR 的文件大小限制不会因后台执行而消失。

### 2.1 企业工作台

前端采用 React、TypeScript、Vite 和 Ant Design，提供企业内部应用风格的工作台：

- 深色侧边导航与顶部系统状态栏，桌面端支持手动收起和展开侧边栏。
- 录音上传、语音转写、纪要生成、人工定稿四步进度轨道。
- 语音转写与智能纪要双栏处理区。
- 明确区分保存定稿、Word 导出和 Markdown 导出操作。
- 支持桌面端、平板和移动端响应式布局。
- 主内容区域填满顶部栏下方的可用空间，仅在内容超出时滚动；会议问答的历史列表与消息区域独立按可用高度滚动。

“模型服务”已提供供应商和模型配置管理；“权限管理”已提供用户、角色和部门树管理。“纪要模板”“团队空间”和“系统设置”目前仅保留导航入口。

### 2.1.1 组织与权限

- 内置系统管理员拥有全部权限，普通成员拥有创建、查看和处理本人会议、会议问答及查看模型配置的权限。内置角色不可修改或删除；管理员可创建自定义角色并配置权限项。
- 用户管理支持创建、编辑、停用、密码重置、角色分配、部门归属和受约束删除。停用或重置密码会撤销已有会话；不能删除或停用最后一名系统管理员。
- 部门树支持顶级/下级部门、排序和移动；禁止移动到自身或下级，含成员或子部门时不可删除。
- 会议权限分为本人、本部门及下级、全部三档；读写权限分别控制，后端对每个会议对象再次校验归属范围，越权对象统一返回 404。模型、问答和组织管理 API 也受权限控制。
- 角色授权在每次请求从数据库计算，变更即时生效；页面根据权限隐藏不可用入口和管理操作。用户的站内通知始终仅对本人开放。

### 2.2 创建会议

用户可以填写会议名称并上传单个录音文件。

支持格式：

- MP3
- WAV
- M4A
- WEBM
- MP4
- MPEG
- OGG

后端校验文件扩展名、空文件和文件大小。默认上限为 200 MB，可通过 `MAX_UPLOAD_MB` 修改。

创建成功后：

1. 原始录音写入 RustFS。
2. 会议元数据写入 SQLite。
3. 普通录音状态设置为 `uploaded`；超过后台阈值的录音设置为 `queued` 并自动开始转写。

### 2.3 语音转写

用户可以对 `uploaded` 状态的会议发起转写。

- `demo` 模式返回固定示例文本，用于无外部服务时走通流程。
- `openai` 模式调用 OpenAI-compatible 的 `/audio/transcriptions` API。
- ASR 模型名称通过 `ASR_MODEL` 配置。
- 第三方兼容服务必须使用该服务实际支持的语音模型名称。

后端从 RustFS 读取录音并写入临时文件。临时文件关闭后再交给 ASR 读取，避免 Windows 上的文件锁冲突；无论转写成功或失败，临时文件都会清理。

转写成功后，文本保存到 SQLite，会议状态更新为 `transcribed`。

### 2.4 生成结构化纪要

只有存在转写文本的会议才能生成纪要。LangGraph 负责调用纪要生成节点，输出统一的 `Minutes` 结构：

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | 字符串 | 纪要标题，1—200 个字符 |
| `summary` | 字符串 | 会议摘要 |
| `key_points` | 字符串数组 | 关键要点 |
| `decisions` | 字符串数组 | 会议决策 |
| `action_items` | 字符串数组 | 行动事项 |

模型输出最终通过 Pydantic 校验。生成成功后，纪要保存到 SQLite，会议状态更新为 `generated`。

### 2.5 人工定稿

用户可以在工作区修改：

- 纪要标题
- 会议摘要
- 关键要点
- 会议决策
- 行动事项

点击“保存定稿”后，修改内容写入 SQLite，会议状态更新为 `edited`。

### 2.6 文档导出

只有 `edited` 状态且包含纪要的会议允许导出。

- Word：生成 `.docx` 文件。
- Markdown：生成 `.md` 文件。

导出内容作为 HTTP 附件返回，同时保存到 RustFS，便于后续归档。

### 2.7 会议记录

会议记录页面提供：

- 按创建时间倒序展示全部会议。
- 按会议名称或原始文件名搜索。
- 按待转写、待生成、待定稿、已完成筛选。
- 展示会议总数、处理中数量、已完成数量和纪要生成率。
- 打开历史会议并继续完成剩余步骤。
- 通过“去对话”直接进入会议问答，并自动关联当前会议。
- 删除会议。

删除会议会同时清理：

- SQLite 中的会议记录、转写和纪要。
- RustFS 中的原始录音。
- RustFS 中的 Word/Markdown 导出文件。

删除操作在前端需要二次确认，且不可恢复。

### 2.8 模型服务与会议问答

模型服务页面支持：

- 管理 OpenAI、Anthropic、Ollama 和 OpenAI-compatible 供应商。
- 配置服务地址、API Key 与启停状态；列表只返回脱敏后的密钥。
- 测试供应商连接。
- 从供应商实时获取可用模型列表，创建模型配置时通过搜索下拉框选择模型标识。
- 分别管理 LLM 对话、会议 RAG 和语音转文字模型。
- 每种用途设置一个启用的默认模型。
- 宽屏下供应商和模型配置两个管理区并排，视口宽度不超过 1100px 时改为单列；模型配置行和状态标签随面板宽度换行，避免横向溢出。

侧边栏“会议问答”提供独立的多轮对话页面。未选择会议时使用默认 LLM 进行普通问答；在输入框键入 `@` 会打开会议列表，可按会议标题或文件名筛选。选中会议后，问答仅使用该会议的转写和结构化纪要作为上下文，并优先使用默认会议 RAG 模型；没有默认会议 RAG 时回退到默认 LLM。切换或取消会议会清空当前对话，避免不同上下文混用。当前实现适用于单场会议上下文，不包含跨会议知识库、Embedding 模型或向量数据库。

左侧历史列表仅显示当前账号的会话，按最近对话时间倒序排列。首次成功回答后创建会话，以首个问题（最多 60 个字符）为标题；“新对话”只清空当前页面状态，发送并成功回答后才保存新会话。打开历史会话可查看全部已保存消息并继续提问，续聊沿用该会话的会议关联。会话的完整原始消息保存在 SQLite 的 `chat_conversations` 表中，其他账号读取或续聊该会话会得到 404。

问答前会估算系统提示、会议内容、已有摘要、未摘要消息和本轮问题的 token 数。达到上下文窗口的 80% 时，先将较早消息与原摘要合并为新摘要，再用摘要和最近消息回答；完整原始消息仍可在历史中查看。摘要及已摘要消息数与会话一同保存，跨请求续聊不会重新发送已摘要的原文。摘要和剩余消息仍超出阈值时会继续滑动；单条消息或会议内容本身超出阈值时返回 413。token 数采用跨供应商估算，80% 为保留回答空间的预警线，不代表精确的模型分词结果。

窗口大小优先从 Ollama `/api/show` 的 `num_ctx` / `model_info.*.context_length`，或 OpenAI-compatible 模型元数据中的 `context_window`、`context_length`、`max_model_len` 等字段读取，并缓存 15 分钟。OpenAI 和 Anthropic 的模型列表接口不保证提供窗口大小，元数据缺失或请求失败时回退到 `CHAT_CONTEXT_WINDOW_TOKENS`（默认 256K，即 262144 token）。该值需要按实际部署模型调整。

## 3. 数据模型与状态

### 3.1 Meeting

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 | UUID 十六进制会议 ID |
| `filename` | 字符串 | 原始录音文件名 |
| `title` | 字符串 | 会议名称 |
| `created_at` | 日期时间 | UTC 创建时间 |
| `status` | 枚举 | 当前处理状态 |
| `transcript` | 字符串 | 完整转写文本 |
| `minutes` | `Minutes` 或空 | 结构化纪要 |

### 3.2 状态流转

```text
uploaded → transcribed → generated → edited → export
```

| 状态 | 页面含义 | 可执行操作 |
|---|---|---|
| `uploaded` | 待转写 | 开始转写 |
| `transcribed` | 待生成 | 生成纪要 |
| `generated` | 待定稿 | 编辑并保存定稿 |
| `edited` | 已完成 | 再次保存或导出 |

`export` 是业务动作，不是数据库中的状态值。

### 3.3 ChatConversation

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 | 会话 ID |
| `owner_id` | 字符串 | 创建者账号 ID，用于查询和续聊隔离 |
| `meeting_id` | 字符串或空 | 首次提问时关联的会议，普通问答为空 |
| `title` | 字符串 | 首个问题截取前 60 个字符 |
| `messages_json` | JSON 字符串 | 按顺序保存的用户与助手消息 |
| `updated_at` | 日期时间 | 最近一次成功回答的 UTC 时间，用于列表排序 |
| `summary_text` | 字符串 | 较早对话的滚动摘要 |
| `summarized_count` | 整数 | 已纳入摘要的原始消息数 |

## 4. 数据存储

### 4.1 SQLite

SQLite 保存结构化数据：

- 会议 ID、名称、文件名和创建时间。
- 当前处理状态。
- 语音转写文本。
- JSON 格式的结构化纪要。
- 按账号隔离的问答会话、会议关联和完整消息。

默认数据库文件：

```text
backend/data/meetmind.db
```

可通过环境变量覆盖：

```dotenv
DATABASE_PATH=backend/data/meetmind.db
```

后端启动存储层时自动创建数据库目录和 `meetings` 表。当前直接使用 Python 标准库 `sqlite3`，没有引入 ORM 或迁移框架。

### 4.2 RustFS

RustFS 只保存二进制文件：

```text
huizhi-meetings/
├── recordings/{meeting_id}/source.{ext}
└── exports/{meeting_id}/minutes.{docx|md}
```

后端通过 boto3 调用 RustFS 的 S3-compatible API，并强制使用 path-style addressing。

首次访问时：

1. 使用 `HeadBucket` 检查存储桶。
2. 仅在明确收到 404、`NoSuchBucket` 或 `NotFound` 时创建存储桶。
3. 403、密钥错误等权限异常直接返回，不会误判为桶不存在。

## 5. 模型与协议

### 5.1 ASR

| `ASR_BACKEND` | 用途 | 关键配置 |
|---|---|---|
| `demo` | 固定示例转写 | 无需密钥 |
| `openai` | OpenAI-compatible 音频转写 | `ASR_MODEL`、`OPENAI_API_KEY`、`OPENAI_BASE_URL` |

ASR 和纪要模型共享 OpenAI 连接配置，但职责独立。配置 OpenAI-compatible LLM 不代表该服务一定支持音频转写。

### 5.2 纪要模型

| `LLM_PROVIDER` | 协议 | 关键配置 |
|---|---|---|
| `demo` | 本地确定性提取 | 无需外部服务 |
| `openai` | OpenAI | `OPENAI_API_KEY`、`OPENAI_BASE_URL` |
| `anthropic` | Anthropic Claude | `ANTHROPIC_API_KEY`、`ANTHROPIC_BASE_URL` |
| `ollama` | Ollama | `OLLAMA_BASE_URL` |
| `vllm` | OpenAI-compatible | `VLLM_BASE_URL`、`VLLM_API_KEY` |

Claude、Ollama 和 vLLM 在第一阶段只参与纪要生成，不提供 ASR 能力。

### 5.3 LangGraph

当前工作流保持最小结构：

```text
START → generate_minutes → END
```

`demo` Provider 使用本地规则生成纪要；真实 Provider 调用模型并要求返回 JSON，再转换为统一的 `Minutes` 模型。

| 方法 | 路径 | 成功状态 | 用途 |
|---|---|---:|---|
| GET | `/api/health` | 200 | 健康检查和当前模型配置 |
| POST | `/api/meetings` | 201 | 上传录音并创建会议 |
| GET | `/api/meetings` | 200 | 按创建时间倒序获取会议列表 |
| GET | `/api/meetings/{id}` | 200 | 获取会议详情 |
| DELETE | `/api/meetings/{id}` | 204 | 删除会议及关联文件 |
| POST | `/api/meetings/{id}/transcribe` | 200 | 执行语音转写 |
| POST | `/api/meetings/{id}/minutes/generate` | 200 | 生成结构化纪要 |
| PUT | `/api/meetings/{id}/minutes` | 200 | 保存人工定稿 |
| POST | `/api/meetings/{id}/questions` | 200 | 基于当前会议内容问答 |
| POST | `/api/chat` | 200 | 普通问答或携带会议 ID 的多轮会议问答；可传 `conversation_id` 续聊，返回 `conversation_id` |
| GET | `/api/chat/conversations` | 200 | 查询当前账号的会话历史，按最近对话时间倒序 |
| GET | `/api/chat/conversations/{id}` | 200 | 获取当前账号的会话及完整消息，其他账号的会话返回 404 |
| GET | `/api/meetings/{id}/export?format=docx|md` | 200 | 导出定稿 |
| GET/POST | `/api/model-providers` | 200/201 | 查询或创建模型供应商 |
| PUT/DELETE | `/api/model-providers/{id}` | 200/204 | 更新或删除模型供应商 |
| POST | `/api/model-providers/{id}/test` | 200 | 测试供应商连接 |
| GET | `/api/model-providers/{id}/models` | 200 | 获取供应商可用模型列表 |
| GET/POST | `/api/model-configs` | 200/201 | 查询或创建模型配置 |
| PUT/DELETE | `/api/model-configs/{id}` | 200/204 | 更新或删除模型配置 |

主要错误状态：

| 状态码 | 场景 |
|---:|---|
| 400 | 文件类型、空文件或导出格式不合法 |
| 404 | 会议不存在 |
| 409 | 未转写就生成纪要，或未定稿就导出 |
| 413 | 文件超过大小限制 |
| 502 | ASR 或纪要模型调用失败 |
| 503 | RustFS 存储不可用（仅上传路径；转写、删除等其他路径的存储故障返回 500） |

## 8. 异常处理要求

### 8.1 上传

- 非支持格式必须拒绝。
- 空文件必须拒绝。
- 超限文件必须返回 413。
- RustFS 写入失败不能创建成功的 SQLite 会议记录。

### 8.2 转写

- RustFS 录音不存在或读取失败时不得更新状态。
- 外部 ASR 参数错误、模型错误或 HTTP 错误统一返回 502。
- 第三方 ASR 返回 400 时应检查模型名称、音频格式和接口兼容性。
- Windows 临时文件必须先关闭再交给 ASR 读取。
- 临时文件必须在 `finally` 中清理。

### 8.3 纪要

- 没有转写文本时返回 409。
- 模型输出不是合法 JSON 或不符合 `Minutes` 时返回 502。
- AI 失败不能覆盖已有有效纪要。该行为目前由代码结构保证（异常在写入纪要前抛出），暂无自动化测试显式覆盖。

### 8.4 删除

- 会议不存在时返回 404。
- 删除范围必须限定在当前会议 ID 对应的 SQLite 记录和 RustFS 前缀。

## 9. 启动与验证

### 9.1 后端

从项目根目录执行：

```powershell
uv sync
Copy-Item backend\.env.example backend\.env
uv run python backend\main.py
```

`backend/main.py` 是可执行入口，`backend/app/main.py` 负责 FastAPI 应用和路由。

### 9.2 前端

```powershell
cd frontend
npm install
npm run dev
```

开发服务器将 `/api` 代理到 `http://localhost:8000`。

### 9.3 自动验证

```powershell
uv run python -m pytest backend/tests -q

cd frontend
npm test
npm run build
```

在 Windows 中建议使用 `python -m pytest`，确保项目根目录进入 Python 模块搜索路径。

后端测试覆盖：

- 配置分组与环境变量。
- 完整上传、转写、生成、定稿和导出流程。
- 会议列表与删除。
- SQLite 持久化行为。
- RustFS 存储桶检查、分页列举和删除。
- Windows 临时文件关闭与清理。
- 多模型 Provider 和纪要输出校验。
- 供应商与模型配置持久化、密钥脱敏、默认模型切换和会议问答接口。
- 后端启动入口。

## 10. 第一阶段边界

以下能力不属于当前完成范围：

- 浏览器实时麦克风采集。
- WebSocket 实时字幕。
- 发言人分离和时间戳分段。
- 转写文本人工纠错。
- 实时进度推送（当前后台转写使用状态轮询）。
- 纪要模板管理。
- 自助注册、SSO 与多租户级权限。
- 多租户数据隔离。
- 全文搜索和会议知识库。
- 数据库版本迁移工具。
- PostgreSQL 或其他服务端数据库。
